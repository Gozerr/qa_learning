# QA Base

Закрытая база материалов для обучения QA. Фронтенд публикуется на GitHub Pages, а Supabase предоставляет авторизацию и базу данных — отдельный VPS не нужен.

## Настройка

1. В Supabase откройте **SQL Editor**.
2. Скопируйте содержимое `supabase-setup.sql`.
3. Перед запуском замените `owner@example.com` на свой настоящий email.
4. Выполните SQL через **Run**.
5. В Supabase откройте **Authentication → URL Configuration** и добавьте URL опубликованного GitHub Pages-сайта в **Redirect URLs**.

Публичный URL и publishable/anon key уже находятся в `app.js`. Секретный `service_role key` сайту не нужен и не должен попадать в репозиторий.

Новые материалы добавляются в таблицу `articles` через Supabase Table Editor. Поле `image_url` может содержать публичную ссылку на картинку.

В форме публикации выберите направление материала:

- **Теория тестирования** — материал появится в разделе «Теория тестирования»;
- **Практика** — материал появится в выпадающем меню «Практика», сгруппированный по указанному подразделу.

Чтобы добавить новый подраздел практики, выберите «Практика» и укажите новое значение в поле категории. Оно автоматически появится в меню после публикации.

## Публикация

1. Создайте репозиторий на GitHub и загрузите файлы в ветку `main`.
2. В настройках репозитория откройте **Settings → Pages** и выберите **GitHub Actions** в качестве источника.
3. Workflow `.github/workflows/deploy.yml` автоматически опубликует сайт после push.

## Как выдавать доступ

Войдите в сайт через magic link на email владельца. Откройте значок шестерёнки, добавьте email участника. Пользователь вводит тот же email на странице входа и получает письмо со ссылкой.

Доступ защищён Supabase RLS: материалы читаются только пользователями, присутствующими в `access_members`. Email, который пользователь ещё не добавил, не получает доступ к материалам.
