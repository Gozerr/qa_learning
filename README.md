# QA Base

Закрытая база материалов для обучения QA. GitHub Pages публикует фронтенд, а Supabase предоставляет magic-link авторизацию, базу данных и Storage.

## Настройка Supabase

1. Откройте **SQL Editor** в проекте Supabase и выполните `supabase-setup.sql`.
2. Перед запуском замените email владельца в `insert into public.access_members`.
3. В **Authentication → URL Configuration** добавьте URL GitHub Pages в **Redirect URLs**.
4. В Storage SQL создаёт публичные buckets `article-images` и `avatars`; загрузка защищена RLS. Публичным ключом в `app.js` можно пользоваться в браузере, секретный `service_role` key не добавляйте в репозиторий.

## Возможности

- magic link и доступ только для участников `access_members`;
- профиль с именем и аватаром (аватар загружается в Supabase Storage);
- отметка теории/практики как пройденной и персональный прогресс;
- мини-тесты после теоретических материалов (таблица `quiz_questions`);
- админ-панель: публикация или черновик, редактирование, удаление, порядок материалов, загрузка изображений, приглашение участников и выдача роли администратора;
- материалы разделяются на теорию и практику по категории.

Владелец открывает панель шестерёнкой, добавляет пользователей email-адресом и управляет материалами. Черновики видны только администраторам.

## Публикация

Загрузите файлы в ветку `main`. Workflow `.github/workflows/deploy.yml` автоматически опубликует сайт через GitHub Pages после push. Проверьте, что в настройках репозитория источником Pages выбран **GitHub Actions**.
